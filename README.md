# codex智入

纯本地运行的 Windows Codex 聊天备份与迁移工具。当前仓库版本：**1.3.5（实验性）**。

**1.3.5 更新：**导入按主聊天选择，关联的内部助手和安全审查自动绑定导入，无需单独勾选；多层助手跟随最近的普通聊天。保留稳定快照、压缩会话、摘要修复和只读诊断功能。仓库中的程序和源码已包含这些修复；旧的 1.3.0 Release 安装包不包含这些更新。

遇到 `Unexpected session file: ...jsonl.zst` 时，请使用完整的 1.3.5 工具包重试。压缩文件是 Codex 支持的会话格式，应保留原文件。浏览时流式读取；导出保留原始压缩文件及哈希；导入仅在隔离目录解压为普通 JSONL 并修正目标数据库路径及历史偏移。数据库仍引用 `.jsonl`、磁盘上只有对应 `.jsonl.zst` 的情况也受支持。两种表示同时存在时与 Codex 一致，优先读取普通 `.jsonl`。

仓库只分发程序、源码、虚构测试和说明，**不存储任何个人聊天记录或登录配置**。原有 GitHub 聊天备份／云端同步方案已停止使用。

> 注意：导入是“安全合并所选聊天”，不是清空目标电脑再完整替换。提示成功只代表所选项完成。冲突聊天及共享历史不兼容的分支可能被跳过；目前不保证任意已有数据、任意 Codex 版本之间的完整迁移。详见[已知问题](KNOWN_ISSUES.md)。

## 下载和运行

使用当前 **1.3.5**，请在仓库主页选择 **Code → Download ZIP**，或[下载 main 分支完整 ZIP](https://github.com/wojiaoxiaoyueyueya/codex-chat-log/archive/refs/heads/main.zip)。完整解压后双击根目录的 `codex智入.exe`，确认窗口标题显示 **1.3.5**。

[Releases](https://github.com/wojiaoxiaoyueyueya/codex-chat-log/releases) 中的旧 `codex-zhiru-1.3.0-Windows-x64.zip` 不包含本次修复；下载时请核对版本。

- 支持 Windows 10/11 x64，需要 .NET Framework 4.8。
- 免安装，自带离线 Python 运行环境，不需要 Git、GitHub CLI、账号授权或联网。
- 不要只复制 exe；`src`、`lib`、`vendor` 必须一起保留。
- 本项目不是 OpenAI 官方迁移工具。

## 内部助手和安全审查随聊天导入（1.3.5）

核对列表只给普通聊天提供复选框。勾选一条聊天时，其关联的内部助手、安全审查及多层子助手自动随附；取消该聊天后，关联记录一并取消。展开聊天下的“随聊天导入”可以阅读内部记录，无需也不能单独勾选。底部及确认窗口分别显示主聊天数和自动随附数。

绑定依据是备份保存的父子关系和会话来源，不按标题或项目名猜测。普通分支仍是独立可选聊天，其助手跟随该分支。正文相同而助手有更新时，主聊天也会列出以便同步关联记录。默认模式遇到组内冲突或本机记录更多时保留整组；明确切换“以备份为准”后才允许采用备份版本。共享历史与数据库兼容检查仍对整组生效，正式导入前保留完整回滚副本。

没有可确认主聊天的内部记录不会自动绑定到其他聊天，核对页会显示数量；原始 `.czr` 保留这些记录。只有备份中存在的关联记录会自动导入，本机独有记录继续保留。旧 `.czr` 包可直接重新核对，无须重导。

## 使用方式

### 旧电脑：一键导出

1. 打开工具，确认数据目录和聊天列表。
2. 保存 Codex 和相关编辑器中的未完成工作，点击“一键导出到桌面”。
3. 根据提示正常退出相关 Codex 会话。工具不会强杀进程。
4. 导出完成后，桌面生成一个 `codex智入-聊天备份-日期-时间.czr` 文件。

`.czr` 是需要携带到新电脑的聊天包，不是工具 ZIP。打包临时文件不是可导入备份。导出不删除源聊天，也不覆盖已有备份。

### 新电脑：导入并核对

1. 把 `.czr` 和完整工具文件夹复制到新电脑。两台电脑建议使用相同版本的 Codex 以及本工具。
2. 建议先在新电脑启动 Codex 并登录一次，之后保存工作并退出。
3. 点击“一键导入／核对”，选择 `.czr`；只核对不会替换聊天。
4. 阅读顶部统计和每条聊天的原因，按需选择，再点击“确认导入所选聊天”。
5. 启动 Codex，逐项检查项目、父对话、分支和历史消息。确认完整前不要删除聊天包或回滚副本。

| 核对结果 | 处理 |
| --- | --- |
| 目标没有的聊天 | 可选择新增 |
| 备份是目标历史的后续 | 可选择更新 |
| 内容相同 | 跳过 |
| 目标是备份历史的后续 | 保留目标，跳过 |
| 双方历史不同 | 保留目标，禁止直接覆盖 |
| 分支所依赖的父历史无法安全复用 | 禁止直接导入该分支 |

这套保守规则可能导致只导入一部分。**不要把“导入了 N 条”理解为“备份内全部聊天已恢复”。** 工具尚未提供任意冲突历史的自动拼接或“冲突另存为独立聊天”功能。

## 确认备份最新，但提示“双方历史不同”

默认比较要求消息和工具记录构成严格的共同前缀。“双方历史不同”表示无法自动判定为连续续写，并不表示本机一定更新。两边分别继续聊天、迁移后的历史事件差异都可能导致这种结果。

已确认备份就是需要恢复的版本时，在 1.3.4 中：

1. 点击“一键导入／核对”，选择原 `.czr` 包。
2. 点击核对页底部的“以备份为准重新核对”。这一步会正常退出相关 Codex 会话，重新读取本机快照并更新选择；尚未写入聊天，无需重新选择备份包。
3. 检查主聊天及分支的勾选，点击“确认导入所选聊天”，阅读替换提示后确认。

此模式允许用备份替换已选的冲突聊天，也允许替换本机记录更多的版本。相同内容的聊天也会列出，便于一并恢复父子关系；不会生成重复聊天。建议保留相关父聊天和分支的默认勾选。本机独有聊天、未勾选聊天及登录配置保留，写入前保存完整聊天回滚副本。

如果本机保留的独有分支依赖一段不同的旧父历史，父聊天仍会标为不可单独替换，并显示具体原因；不会通过跳过共享历史检查来覆盖。此功能不自动拼接两份不同对话，实际结果仍需在 Codex 中核对。“切回保留本机”可撤销本次优先策略；重新选择备份时恢复默认策略。

如果在旧版点击策略按钮时看到“本机记录或配置已变化”，请改用 1.3.4 重新选择原包。旧版的浏览可能在源数据库旁生成 WAL/SHM 辅助文件，误触发严格的文件变化检查。新版浏览只读取独立文件副本；策略切换会更新本机快照及冲突结果，页面显示“已重新读取本机快照”。若此后又在 Codex 中续写或修改数据，正式导入仍会停止，以免按过期核对覆盖。

## 功能与边界

- 普通聊天、归档、项目分组、分支和共享历史的离线打包。
- 保留原始对话文字，逐文件 SHA-256 校验；导入前保留回滚副本。
- 保护目标端登录文件及配置，不迁移账号登录状态。
- 长任务在后台进行；只读浏览副本准备好后可继续阅读、翻页、搜索、复制。
- 对话支持常用 Markdown 排版，不执行历史 HTML、命令或链接。
- 有限兼容已知的可空历史元数据字段，不伪造 Codex 数据库迁移记录。

不包含项目源码、工作区文件、插件、浏览器登录或云端不可访问的聊天。聊天引用的外部图片或文件需要自行迁移。不是 macOS/Linux/ARM 原生程序。

## 已导入，但 Codex 列表看不到

在**出现问题的目标电脑**解压完整的 1.3.5 工具包，双击 `diagnose.cmd`。默认只读，不退出 Codex、不修改真实数据库；SQLite 数据库及 WAL 先复制到临时目录后再查询。工具目录会生成 `codex-diagnostic-日期-时间.txt`，报告只包含数量和原因，不包含正文、标题、会话编号、账号或路径。

也可指定数据目录和原备份包，以区分“没有入库”和“入库后被列表过滤”：

```powershell
.\diagnose.cmd -CodexHome 'D:\CodexData' -Bundle 'D:\备份\聊天.czr'
```

| 报告字段 | 含义 |
| --- | --- |
| `bundle_comparison.absent_from_target` | 备份中有，但目标数据库没有的聊天；检查导入选择、冲突和分支依赖 |
| `counts.ordinary_active_empty_preview` | 活动普通聊天的列表摘要为空，可能被 Codex 的默认列表过滤 |
| `counts.repairable_previews` | 有已保存的首条用户摘要，可安全补齐空 `preview` |
| `counts.missing_transcript_paths` | 数据库引用的会话文件不存在，需检查旧电脑绝对路径或文件是否复制完整 |
| `counts.missing_workspaces` | 工作区目录不存在，需要迁移源码并检查项目路径 |

如果 `repairable_previews` 大于 0，保存工作并**正常退出 Codex、CLI 及相关编辑器会话**，再执行：

```powershell
.\diagnose.cmd -RepairPreviews
# 自定义数据目录时必须继续指定同一个目录：
.\diagnose.cmd -CodexHome 'D:\CodexData' -RepairPreviews
```

修复仅用数据库已有的 `first_user_message` 补齐空 `preview`，保留已有非空摘要、对话文件和历史内容。发现 Codex 仍在运行就停止，不自动退出或强杀应用。修改通过已有事务安装流程进行，先保留独立回滚工具；需要撤销时使用回滚目录内的 `恢复到导入前.cmd`。

`preview` 缺失是可复现的一种原因，并非所有“看不到”问题的解释。诊断不能证明完整真机恢复，也不会自动拼接冲突分支或重建缺失的历史。未直接引用的 JSONL 可能是共享历史分段，不能据此删除。

## 隐私和回滚

`.czr` **没有加密**，保留聊天原文，可能包含曾经粘贴的密码、密钥或工作资料。不要把它上传到本仓库、Issue、公开网盘或公共 Release。

每次正式导入前保存回滚目录，实际位置会在成功提示中显示。可使用“恢复到导入前”，或备份目录中的独立 `恢复到导入前.cmd`。确认完整前不要清理回滚目录。

本仓库内的测试是临时生成的虚构数据；不包含开发者的聊天快照、数据库、诊断包或真实聊天截图。更多要求见 [SECURITY.md](SECURITY.md)。

## 源码结构

| 文件 | 用途 |
| --- | --- |
| `codex智入.exe` | 用户运行入口 |
| `src/App.cs` | Windows WPF 界面、后台工作与预览交互 |
| `src/RichMessage.cs` | 本地 Markdown 排版和复制 |
| `src/offline.py` | 扫描、浏览副本、离线包、核对、导入和回滚流程 |
| `diagnose.cmd`、`diagnose.ps1`、`src/chat_diagnostics.py` | 目标电脑只读可见性诊断、与原包核对、显式摘要修复 |
| `src/sidebar.py` | 侧栏项目、置顶、分支和内部助手分类 |
| `src/win_process.py` | 进程识别与正常退出请求 |
| `src/asset_conflicts.py` | 附件同名冲突分别保留 |
| `lib/chat_merge.py` | 隔离合并、历史位置修复、已知字段兼容、事务回滚 |
| `lib/chat_select.py` | 内容比较、选择及共享历史依赖检查 |
| `lib/chat_snapshot.py` | 复用的本地快照辅助函数；不是 GitHub 上传入口 |
| `vendor/` | 自带 Python 运行环境及其随附许可证 |
| `tests/`、`lib/test_chat_*.py` | 虚构数据与界面回归测试 |

旧的 `UPLOAD-CHAT-BACKUP.cmd`、`UPDATE-CHAT-RECORDS.cmd`、GitHub 下载脚本和云端聊天分卷不是本版本的使用方式。
